# Field-tested engineering guardrails — FT-001..FT-008

**Status:** User-reported recurring mistakes during two weeks of agent use; mandatory behavioral guardrails for R1. Do not silently override. These are cross-cutting and apply alongside AR/OI/BJ/CA/VW references.

- **FT-001 — No dangerous Git actions (hard prohibition).** Never execute `git commit`, `git push`, or Git operations that modify history, the index, branches, tags, remotes, or delete/discard user work (`reset`, `clean`, `rebase`, `checkout`/`switch` of branches, force operations, etc.). Do not stage changes. Read-only `git status`, `git diff`, `git log`, and `git show` are permitted. Leave changes uncommitted for the developer.
- **FT-002 — No SQL firing from Pundit authorization rules (hard prohibition).** Inside policy authorization predicates (`show?`, `update?`, `create?`, and custom `...?` checks), never execute SQL or materialize database relations. Disallowed examples include `exists?`, `any?` when it queries, `count`, `pluck`, `find`, `first`, and equivalent query execution. **Pundit Scope#resolve is explicitly exempt:** database querying and relation construction are permitted there. Ordinary policy predicates must operate on already-available authorization context; inspect existing code for an approved data-preparation approach. Do not conflate relation building with executing SQL.
- **FT-003 — Never edit lib/jumpstart source (hard prohibition).** If customization requires changing a file under `lib/jumpstart/`, never modify that file in place. Check whether a corresponding override already exists under `app/`. If not, copy the file to the correct repository-established location under `app/` and make the smallest necessary changes **only** to that copy. Verify the app override loading mechanism; if location/loading is uncertain, ask rather than inventing the path.
- **FT-004 — No ERB variable initialization or assignment (hard prohibition).** Never add or initialize local or instance variables inside `.html.erb` or other ERB views. Prepare data in controllers, interactors/business layer, or decorators as appropriate; pass prepared values via locals/instance variables. Simple reads are fine.
- **FT-005 — No added code comments (hard prohibition).** Do not introduce inline comments, explanatory comments, block comments, or TODOs in edited application code. Preserve existing comments unless removal is directly required for the task. Documentation requested explicitly is separate from application code.
- **FT-006 — Replicate, never improvise (hard constraint).** If asked to follow or replicate an existing implementation, locate the actual reference, inspect its complete relevant behavior and integration points, and reproduce the pattern with only requested substitutions. Do not invent abstractions, branches, error behavior, names, APIs, or extra features. If reference is unavailable, ask or mark blocked.
- **FT-007 — Preserve styling (hard constraint).** Follow the adjacent repository style, template conventions, CSS classes, format, ordering, naming, and spacing. Do not create new styling patterns unless directly requested. If a style source is named, replicate it faithfully.
- **FT-008 — Minimum diff (hard constraint).** Make the minimum lines of code additions/deletions necessary for requested behavior, no more and no less. Avoid unrelated refactors, formatting churn, broad renames, speculative improvements, and new dependencies. Review the final diff. This does not justify skipping required correctness or safety changes; ask if essential changes exceed scope.

## Validation limits
The included checker is intentionally heuristic: inspect its flagged findings manually. SQL execution in Pundit policies requires runtime/AST verification (a bare `.where` may only build a relation; `.any?` may fire SQL depending on loaded state). Verify `lib/jumpstart/` protection and minimum-diff behavior against `git diff --name-only` and `git diff`, not a whole-repo scan alone. Dangerous Git operations must be prevented **before execution**; a post hoc code scanner cannot enforce tool-use policy.
